rF2SkrOverlayPublic is a plugin that draws a driving HUD straight into the rFactor 2 picture: radar, gear and speed, pedal and force-feedback trace, lap delta, relative timing, fuel and tyre data, tyre temperatures, an overhead track map, an FFB frequency graph and a few audio cues. It learns from your own driving (fuel use, pit-lane speed limit, shift points, best laps) and saves it per car and track.

Every panel can be shown or hidden and moved or resized in game, and the layout is remembered separately for each car. The pictures below are drawn diagrams to show the layout and colours; they are not screenshots.

Why it draws inside the game

Most sim-racing overlays (SimHub dashboards, Discord, MSI Afterburner's on-screen display and many HUD apps) are a separate, transparent window laid on top of the game. That costs more than it looks.

Windows can deliver a game's frames to the screen in two ways. With Independent Flip, each finished frame goes straight to the display, and a G-Sync/FreeSync monitor can refresh the moment a frame is ready. With Composed Flip, every frame first goes through the Windows desktop compositor (DWM) so it can be layered with whatever else is on screen. As soon as another window sits over the game, even a fully transparent, click-through one that draws nothing, Windows has to use Composed Flip for every frame for as long as that window is there. That adds latency and takes the direct hand-off away from variable refresh, which is why transparent overlays get blamed for stutter and input lag.

rF2SkrOverlayPublic doesn't use a window at all. It hooks rFactor 2's own DirectX 11 output and draws the HUD into each frame just before the game hands it to Windows, so the game keeps the direct path. It still does a small amount of drawing work every frame; the frame-time stats panel shows what your frames cost.

Tip: cap your frame rate a few FPS below your monitor's refresh rate (rFactor 2's own limiter or RTSS). Frames above the refresh rate are never shown, cause tearing, and push a G-Sync/FreeSync monitor out of its variable-refresh range.

Installing

  1. Close rFactor 2.
  2. Copy rF2SkrOverlayPublic.dll into <Steam>\steamapps\common\rFactor 2\Bin64\Plugins\.
  3. Start rFactor 2. If the HUD does not appear, go to Settings → Gameplay → Plugins, switch rF2SkrOverlayPublic on and restart the game.

A settings file, rF2SkrOverlayPublic.ini, is created next to the DLL on first run.

Requires 64-bit rFactor 2 running DirectX 11, and the Microsoft Visual C++ 2015–2022 x64 runtime (most sim PCs already have it). It does not work in Le Mans Ultimate: LMU runs plugins in a separate process, so they cannot draw into the game picture.

Updating

Close rFactor 2 and replace the DLL. Your rF2SkrOverlayPublic.ini and everything the plugin has learned are kept. If you still have an earlier release, rF2SkrOverlay.dll or rF2RadarOverlay.dll, delete it, or both will run and draw on top of each other. This release starts with fresh settings in its own rF2SkrOverlayPublic.ini; the learned fuel, pit-limit, shift-point and best-lap data is shared with the earlier releases and carries over.

Version numbers

The version is the date it was built, then a build count: year.month.day.build. For example, 26.11.11.2 is the second build made on 11 November 2026. A higher number is always a newer version. The version is shown at the top of this guide and near the bottom of the in-game shortcut list.

Uninstalling

Close rFactor 2 and delete rF2SkrOverlayPublic.dll and rF2SkrOverlayPublic.ini from Bin64\Plugins. The learned data folders listed under Settings & files can be deleted too.

Controls

KeyWhat it does
Ctrl+Shift+1Opens the shortcut list: every panel, plus the gear-box, track map and cover box settings. Click a row to switch it.
Ctrl+Shift+2Layout mode. Drag any panel to move it, and drag its corner handle to resize it. Positions are saved automatically.
Ctrl+Shift+HTurns the whole overlay off and on.
Mouse cursor: clicking rows in the shortcut list and dragging panels in layout mode both need the mouse cursor on screen. rFactor 2 hides it while you drive, and the plugin can't show it itself: that is rFactor 2's own Toggle Cursor control. It starts unbound, so first assign it a key or button in rFactor 2's settings, then press it to show or hide the cursor. The layout-mode banner shows which key it is on, or "not bound".

Every panel also has its own hotkey slot. They ship unassigned, so you can give any panel a key in the [Shortcuts] section of the INI (a letter, a digit or F1–F12, always used with Ctrl+Shift).

Radar and side bars

A top-down radar around your car. Other cars are drawn at their class's real size and orientation: GT3, GT4, GTE, TCR, prototypes, single-seaters, NASCAR, IndyCar, trucks and more. A car close enough to matter turns red.

Side proximity bars run down the left and right edges of the screen while a car is alongside you, for your peripheral vision. They are triggered by exactly the same rule that turns a radar blip red. How close the car is shows in the bar's strength. Its shape leans towards the end of your car the other car is at. Two cars alongside on one side read stronger than one.

An optional safety margin around every car can be set with [Radar] FootprintBufferMeters.

Gear and speed

Gear and speed on a dark panel, with a small box to the left of the gear digit that only appears when it has something to say.

Gear digit

  • Red flash when the revs are near the shift point.
  • Blue flash is the "shift now" cue. Its target RPM is learned from your own full-throttle upshifts, separately for each gear, and it fires early by your own measured reaction time, so the shift lands on target.
  • Red background when you sit in neutral for more than 0.2 s. A quick pass through neutral on an upshift doesn't trigger it. There is also an optional first-gear warning.

Speed box

Tints amber while a wheel locks under braking and cyan while a wheel spins under power.

The small box (left of the gear)

  • PIT while the pit limiter is on: green at or under the pit-lane limit, blinking red over it. The limit is learned the first time you drive with the limiter on, and saved per car and track. It stays amber until then.
  • ABS flashes amber and TC flashes cyan while the car's ABS or traction control is acting. These are the same colours as the brake and throttle in the pedal trace. ABS is detected from the brake pressure at each wheel. Each can be switched off in the shortcut list.

Shift stats, a separate small panel, shows how you actually shift: average and earliest shift RPM, per gear, and your reaction time to the cue.

Tyre lockup box

A 2×2 box next to the speed readout, one square per wheel in the car's real layout. Each square lights up while that wheel locks under braking: the more it locks, the brighter it gets.

Pit-limiter reminder

When you are coming in for a stop and are already at or under the pit-lane speed, but the limiter is still off, the plugin gives one long beep and shows a warning until you press it. It only does this near the pit entry, whose exact position for each track is learned the first time you drive into that pit lane.

Pedal trace

A scrolling history of the last few seconds:

  • Throttle and brake. A bright line shows what you pressed. A darker line underneath shows what the car actually used after ABS or traction control.
  • Force feedback, centred on the middle line. Up means the wheel is being pushed right and down means left. The top and bottom edges are 100%, so a line pinned flat against an edge is the force feedback clipping.
  • Marks where a wheel locked or spun.

Lap delta and speed strip

The delta bar shows how far ahead or behind you are, compared at the same point on track, against two references:

  • Session best: your fastest lap this session.
  • Best: your all-time best for this car and track, saved across restarts.

Each row can be shown or hidden on its own.

The speed strip above it shows two strips, each one whole lap from left to right: your last completed lap on top and the lap you are on below, filling in as you drive. Each small slice of track is green if you carried more speed through it than the reference lap, and red if less. The delta bar tells you how much time you have gained; the strip tells you where.

A small DRS sign appears under the bar when DRS becomes legal and while it is open.

Relative timing

In a race: the leader plus the cars just ahead of and behind you in the race order. How many are shown is set with the slider in the shortcut list. In practice and qualifying: the cars physically closest to you on track.

Fuel, tyres and brake bias

Three boxes, each of which can be shown or hidden on its own.

Fuel

Fuel left in time and laps. In races it also shows fuel needed to finish and how much over or short you are. Consumption is learned per car class and track from your clean laps; pit laps, refuels and outliers are ignored, and the session's fuel multiplier is allowed for. In practice and qualifying it shows how long the current stint has run.

Tyres

Wear in % per lap for each tyre, under one header. Below that is the time left until your most worn tyre reaches 20% life, naming which tyre it is. In races there is also a projection of tyre life at the finish.

Wear plots (can be hidden on their own) show each tyre's wear per lap over the session as a small box plot. The tyre wearing the most also gets a bigger plot, with a dot for the lap you are on: it moves along as the lap goes on and is green on your usual wear, orange a little over and red well over.

Brake bias

The current brake bias, and how far you have moved it since getting in the car.

Tyre temperatures

After each corner, three bars per tyre show the peak surface temperature across the tread (outside, middle, inside), laid out like the car seen from above. All four tyres share one scale, so they compare directly. The hottest zone on any tyre is full height.

Colour shows the temperature itself: cold, in the window and hot. The tyres that carried the load in that corner are drawn brighter. It is meant for judging camber: inside a little hotter than outside is the usual target.

Track map

An overhead map of the circuit with a dot for every car and a label for each, your own car highlighted. The map is recorded from your own first clean lap at a new track and saved, so it is there straight away next time. If TinyPedal is installed and has already recorded the track, its map is used instead ([TrackMap] TinyPedalMapDir). The box fits the shape of the track, and a small N arrow shows north.

Colouring by mini-sector

The lap is split into equal mini-sectors (80 by default, set with a slider in the shortcut list), and each one can be coloured against a reference:

  • green where you were faster and red where you were slower;
  • purple where you matched or beat the fastest time anyone in your class has set through that mini-sector this session.

The reference is off, your personal best, your session best or the session's fastest lap by anyone in your class. Click the row in the shortcut list to change it, or use wheel buttons 30 and 31 (set in [TrackMap] as DeltaPrevButton/DeltaNextButton).

Rotation, mirror and re-record

Each circuit's map can be turned to any angle, mirrored, or thrown away and recorded again on the next clean lap, from the shortcut list or the controls under the map in layout mode. The setting is kept for that circuit.

FFB spectrum

Shows which frequencies the force feedback rFactor 2 sends to your wheel contains, live. The frequency axis uses the same points as Moza Pit House's FFB equaliser (0, 5, 10, 15, 25, 30, 40, 50, 60, 80, 100 Hz), with finer ticks between them, so you can read it straight across to your EQ.

  • 0–5 Hz: the steady weight of the steering through a corner.
  • 5–25 Hz: kerbs, bumps and the car moving around.
  • 25 Hz and up: road texture, vibration and grain.

The vertical axis is a log scale in % of full force, so small details are still visible next to the big steering forces.

Clipping % (top right) is how much of the last 10 s the force spent at 100%. While it is clipping, changes in force are cut off, so you feel nothing until it drops back below 100%. Short clips on kerbs are harmless. Steady clipping through fast corners means the car's FFB setting is too high for that car.

The red line is the spectrum at the moment it last clipped, fading out over 2 s. It shows what pushed it over the limit. Red highest at the low end means the corner load itself; red in the middle means kerbs or bumps.

The title shows the signal's own rate (normally 400 Hz). This graph reads what the game sends; your wheel base's own filters and EQ act on it after that.

Cover boxes

Plain rounded boxes you can place anywhere, to hide part of the car's own dashboard or in-car display that competes with the overlay. Up to four, each moved and resized (width and height separately) in layout mode.

All the boxes share one shade, from black to white, and one opacity, both set with sliders in the shortcut list. They are drawn underneath every other panel. Off by default: switch on Cover boxes in the shortcut list, then place them in layout mode.

Sounds and cues

CueWhat it does
Pit-limiter reminderOne long beep, plus a warning on screen, if you are at pit-lane speed near the pit entry for a stop with the limiter still off.
DRSA double beep when DRS becomes legal to use, plus an "OPEN DRS" or "DRS ENGAGED" sign under the delta bar.
Have your audio device switched on before starting rFactor 2. The game itself can crash while loading a car if it starts with no sound device.

Braking-point beep

Beeps just before each place where you started braking on your best lap of the session, as a reminder of where your braking point was. It is off by default: switch on the Brake cue + beep row in the shortcut list (or set ShowBrakeCue=1 in [Shortcuts]).

  • It needs one complete, valid lap first. When you set a faster lap, its braking points replace the old ones.
  • The beep comes 0.3 s before the braking point ([BrakeCue] LeadTimeSeconds), so that with a normal reaction your foot reaches the pedal at about the right place.
  • Only big stops beep. The Brake beep slider in the shortcut list sets how much speed a stop must lose on your best lap to get a beep, from every braking point up to 150 km/h. The default is 50 km/h.
  • A small Brake React box near the bottom of the screen shows how long you took to touch the brake after each beep (the average and the last one). It moves and resizes in layout mode like the other panels, and can be hidden with [BrakeCue] ShowReactionStats=0.
  • The pitch and length of the beep are BeepFrequencyHz and BeepDurationMs in [BrakeCue].
The beep follows your own best lap, not an ideal one. Treat it as a reminder, not a target: if you find you can brake later, do, and the next best lap moves the beeps with you.

Frame-time stats and clock

A fixed-size box with FPS and frame time. More stats can be switched on in the [FrameLatency] section of the INI: CPU and GPU time per frame, FPS range with 1% low, game RAM, VRAM, and GPU power (AMD cards). This box also stays up in the menus as a sign the plugin is running. A small clock can be shown as well.

Settings and files

Everything the shortcut list and layout mode change is saved automatically. Everything else (colours, thresholds, which stats show, hotkeys) is in Bin64\Plugins\rF2SkrOverlayPublic.ini. Edit it with the game closed; new values take effect on the next start.

Layouts per car

Which panels are shown, where they sit and how big they are is remembered separately for each car model. The first time you drive a new car it starts from your current layout; after that, getting into a car brings back the layout you last used in it.

Text font

Two rows near the bottom of the shortcut list change the font used for all the overlay's text. Click Text font to cycle through Auto, Consolas, DejaVu Sans Mono, Lucida Console and Courier New, and Text weight to cycle through Light, Normal and Bold. The change shows straight away and is saved.

Auto uses Windows' Consolas font, or DejaVu Sans Mono, which is built into the plugin, when Consolas isn't installed. That is the case when running the game on Linux through Steam (Proton), where Consolas, Lucida Console and Courier New are usually missing too, so picking them shows DejaVu Sans Mono instead. If the text looks thin or hard to read, try Normal or Bold.

Optional diagnostic logging

Off by default. Turn these on in the INI only if asked to, because they make the log much larger:

  • [RelativeTiming] LogRaceGaps=1 — race gaps every 10 s.
  • [LapDelta] ShowValidityDebug=1 — a small on-screen line under the delta bar showing whether rFactor 2 is counting the current lap (useful if the delta bar never shows a reference).

Source code and licence

The full source code is in the source folder. To build it, run build.bat, which writes the DLL to build\. It needs the Visual Studio C++ build tools. The first line of build.bat calls vcvars64.bat at the default Visual Studio 2026 Build Tools location; change that path if your Visual Studio is installed elsewhere. Python is optional: it only stamps the version number.
